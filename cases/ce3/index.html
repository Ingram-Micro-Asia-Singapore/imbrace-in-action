    4How it's built

    What was built in iMBrace

    Data

    DataIQ boards hold the rules and the records:

    • Device Service Catalogue: services, the devices each covers, keywords, and the device count from which a manager must approve (10).
    • Service Centre Slots: room and capacity per slot.
    • Service Enquiries: status, booking ref and version, the customer's words, missing items, slots offered, choice and approval.
    • Customer Slot Choices, Fleet Booking Decisions and Service Bookings.

    Logic

    1. The customer writes in the web chat. AI passes their words to the "Check a Service Enquiry" skill, a FlowOps flow.
    2. Code in the flow reads the catalogue and the words, and either asks for what is missing or writes the enquiry.
    3. A board automation starts the booking flow, built in FlowOps. It posts the free slots into the chat and pauses, waiting for the customer.
    4. Extra steps built in FlowOps, added to the chat workflow iMBrace created, record the customer's slot choice, and the same run resumes.
    5. Code checks the choice was a slot actually offered. If the devices are at or over the catalogue's approval size, the run pauses again for a manager.
    6. The manager adds a record on Fleet Booking Decisions and presses SAVE, naming the booking version.
    7. A second automation starts a flow that checks the decision, and the run resumes.
    8. Code re-checks the slot's room, writes the booking and confirms in the chat.

    AI setup

    One AgentIQ agent, the Service Booking Assistant, on deepseek.v3.2 at temperature 0, with Chat History Memory off. Its one skill is "Check a Service Enquiry". It has no booking tool, so only the flow can book.

    How people reach it

    Customers use the iMBrace hosted web chat, a Web Widget in ConnectIQ. The manager works in the DataIQ decisions board.
