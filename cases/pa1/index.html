    4How it's built

    What was built in iMBrace

    Data

    Two DocIQ document models define what to read.

    • Supplier Invoice: supplier name, invoice number, date, PO number, currency, subtotal, tax, total.
    • Insurance Claim: claim reference, policy number, claimant, claim type, incident date, currency, amount claimed.

    Each model has a document board with Status and Issues columns and a "Current" view. Three DataIQ reference boards, filled by CSV import, hold Supplier Master, Open Purchase Orders and Insurance Policies. Three more hold the Exceptions Worklist, Review Decisions and the demo finance and claims destination.

    Logic

    1. A document is dropped into DocIQ. AI picks the model and reads the values with a confidence mark.
    2. A board automation starts the "Check and Route" workflow built in FlowOps.
    3. Code checks every value against the reference boards, looks for duplicates, and requires DocIQ to be confident in every value it relies on.
    4. Code routes the document: post to the demo destination, hold on the worklist with the reason, or mark it duplicate.
    5. A reviewer corrects a value or adds a decision in a DataIQ form.
    6. A second automation starts "Apply Review Decisions". Code re-checks before posting an approval or recording a rejection.

    AI setup

    No AgentIQ agent is used. The AI is DocIQ's own document reader, which chooses between the two models from their descriptions and returns each value with its confidence. All judgement after that is fixed code reading the boards.

    How people reach it

    Staff drop invoices and claims onto the DocIQ Document Boards drop zone. Held documents, reasons and decisions are worked in DataIQ boards and forms. Record History shows each change.
